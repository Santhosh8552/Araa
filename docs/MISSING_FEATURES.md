# ARAA Company Trading Platform — Missing Features & Gap Analysis (`MISSING_FEATURES.md`)

**Comparison Target:** `ARAA — FULL COMPANY PLATFORM DEVELOPMENT PROMPT` (Company-Owned Prop Desk: Zerodha Kite Connect + CoinDCX Spot) vs. Current `AraaBot-Online-Production-Ready` Codebase.

---

## Summary Gap Table

| Area | Status | Gap Description | Target Phase |
| :--- | :--- | :--- | :--- |
| **1. Company Entity & Employee RBAC** | **NOT IMPLEMENTED** | No `companies`, `company_users`, `roles`, or `permissions` enforcement for the 7 specified roles (`Company Director`, `Super Admin`, `Finance Admin`, `Trading Admin`, `Risk Manager`, `Technical Admin`, `Auditor`). Existing auth is customer `users` + single `ADMIN_USERNAME` token. | Phase 2 |
| **2. Mandatory TOTP MFA & Session Revocation** | **PARTIAL** | 6-digit sandbox OTP exists in `saas_manager.py` (`user_security_tokens`), but true Authenticator TOTP MFA (`pyotp`), backup codes, and per-employee session revocation list do not exist. | Phase 2 |
| **3. Independent Capital Pools (India vs. Crypto)** | **NOT IMPLEMENTED** | No `company_capital_pools` / `capital_allocations` isolation. Current code reads a single wallet (`deposit_balance` + `profit_balance`) or single `broker_connections` balance. Cross-market capital checks do not isolate India INR vs. Crypto. | Phase 3 |
| **4. Precise Financial Arithmetic (Paise / Decimal)** | **NOT IMPLEMENTED** | `backend/database.py` uses binary float `REAL` for all monetary quantities, prices, and ledger entries (`wallets`, `positions`, `trades`, `ledger_entries`). Must migrate to integer `paise` (INR) and string/numeric `Decimal` (Crypto). | Phase 3 |
| **5. Zerodha Kite Connect Adapter** | **NOT IMPLEMENTED** | Missing OAuth login URL generator, `/callback` request-token exchange, SHA-256 checksum verification, daily session renewal workflow, NSE/BSE instrument master sync, margins/holdings/positions/orderbook/tradebook/LTP/OHLC APIs, and Zerodha mock adapter. *(External dependency: Kite Connect developer app + registered static IP).* | Phase 4 |
| **6. CoinDCX Company Spot-Only Adapter** | **PARTIAL** | `coindcx_gateway.py` is built primarily for leveraged USDT perpetual futures and per-user rows. Needs dedicated Spot-only company adapter enforcing pair precision/min-notional metadata, no leverage/futures, withdrawal-disabled verification, and zero synthetic fills. | Phase 5 |
| **7. Universal Broker Manager (No Global State)** | **PARTIAL** | `exchange_adapter.py` has a basic 4-method ABC; `real_broker.py` uses a global mutable `_EXCHANGE_CLIENT`. Missing full 14-method `BrokerAdapter` contract (`validate_instrument`, `calculate_margin`, `place_order`, `get_order_status`, `get_trades`, `cancel_order`, `disconnect`) with per-account secret decryption. | Phases 4–5 |
| **8. AI Signal / Order Intent Decoupling** | **PARTIAL** | `bot_engine.py` directly opens/closes internal trades and mixes paper simulation paths. Must be refactored to emit `signals` -> `order_intents` -> `RiskGuardian` -> `OMS`, without touching live broker APIs directly. | Phases 6–8 |
| **9. 16-State OMS & Timeout Safety** | **PARTIAL** | Current `oms_engine.py` uses 8 states and lacks explicit `UNKNOWN`, `RECONCILIATION_REQUIRED`, `SUBMISSION_PENDING`, `CANCEL_PENDING`, idempotency-key uniqueness constraint, and "query broker before retry" timeout recovery. | Phase 8 |
| **10. Company Ledger & Accounting Exports** | **PARTIAL** | Current `financial_ledger.py` records SaaS brokerage/deposits in float. Missing immutable company-only events (capital additions/withdrawals, tax/charges breakdown, adjustment entries, broker-confirmed vs. manual distinction). | Phase 9 |
| **11. Automated Reconciliation Engine** | **PARTIAL** | `ExecutionReconciliationEngine` exists as a stub in `oms_engine.py`. Missing scheduled/pre-trade/post-trade reconciliation across balances, open orders, trades, positions, and fees, `reconciliation_runs`/`reconciliation_differences` tables, and automatic trading halt upon mismatch. | Phase 9 |
| **12. Strict Paper vs. Live Isolation** | **PARTIAL** | Current DB mixes `is_live` flag inside shared `orders`/`positions` tables and `real_broker.py` returns `fallback_to_paper=True`. Must forbid any live-to-paper fallback and isolate paper accounts/tables strictly from company capital. | Phases 8–9 |
| **13. 20-Page White/Navy Company Control Center UI** | **PARTIAL** | Current UI is Vanilla HTML/JS dark-theme retail terminal (`frontend/`, `admin/`). Missing Company Profile, Employee RBAC, Capital Pool Allocator, Zerodha Login Renewal UI, Reconciliation Differences Inspector, and Compliance Tracker. Also requires resolving Section 24 (`React` vs. extending Vanilla JS). | Phase 10 |
| **14. Compliance & Regulatory Evidence Module** | **NOT IMPLEMENTED** | Missing company KYC/incorporation record tracker, algo approval checklist (SEBI/exchange/FIU-IND review tracking), static IP evidence log, and API permission audit logs. *(Requires legal/CA review externally).* | Phase 10 |
| **15. Walk-Forward / Look-Ahead-Safe Backtesting Upgrades** | **PARTIAL** | `backtest_engine.py` handles fees/slippage/Sharpe, but lacks out-of-sample split controls, expectancy/MAE/MFE metrics, and market-session hour enforcement (NSE 09:15–15:30 IST). | Phase 11 |
| **16. PostgreSQL, Versioned Migrations, Redis & Production Stack** | **NOT IMPLEMENTED** | No `migrations/` versioned SQL runner, no PostgreSQL `DATABASE_URL` SQL dialect layer (SQLite `?` placeholders used across all modules), no Redis worker queue, no Nginx TLS reverse proxy, and no automated `pg_dump`/restore test scripts. | Phases 2 & 12 |
